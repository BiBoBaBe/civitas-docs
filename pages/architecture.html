Civitas is written in TypeScript on Bun, with no runtime dependencies. This page is for anybody who wants to know how the promises on the rest of the site are kept. It assumes no more than curiosity.

The log is the only thing that is written

The world is an append-only log of events. World state is a fold over that log: start from nothing, apply every event in order, and you have the world as it stands. Nothing else is ever written. A view, a brief, a journal, a person's current feelings: all of them are computed from the log when asked.

The event alphabet is five primitives. Everything reduces to them:

node_added      a person, place, fact, situation, plan, term... came into existence
edge_added      a link between two nodes opened: AT, KNOWS, FEELS, BELIEVES, OWES...
edge_closed     a link ended
node_patched    a node's own fields changed
time_advanced   the clock moved

On top of them sit derived events, which compose primitives in one named step so the log reads like a history rather than a diff: moved, granted, transferred, spent, texted, watched, appearance_changed, activity_set, loosened, and the two declarations a world makes about what it counts and what kinds of situation it has.

Every event carries when it happened in world time, why it exists, who could perceive it, and a significance from 0 to 1:

interface WorldEvent {
  id: EventId;          // derived from branch and position, never random
  at: WorldTime;        // fictional minutes
  type: EventType;
  payload: ...;
  causedBy: { kind: "authored" } | { kind: "verb"; verb; messageId } | { kind: "tick"; seed } | { kind: "event"; event };
  witnesses: PersonId[];
  salience: number;     // 0..1
}

The graph is temporal

The folded state is a typed graph. Twelve kinds of node: person, place, faction, item, fact, thread, plan, alias, task, offer, term, pair. Links between them carry a type and, always, a since and an until. A link with no until is still true.

Links are closed, never deleted, so history stays walkable. "Where was she at eight last Thursday" is a query over links that were open at that minute. Every link also carries a provenance: authored, witnessed, told, or inferred. See What people know.

The data model deliberately holds less than it could. A person has no stored drives, no stored level-of-detail tier, no stored list of what they witnessed. Each of those is derivable from the graph, and a stored copy would be a second source of truth kept in step by hand.

Determinism

The same log always replays the same city. Four things make that true.

  1. Fictional time is its own type. The real clock cannot be passed where world time is expected without a compile error.
  2. Event ids are derived from the branch and the sequence number, never generated at random.
  3. Randomness is seeded. Every stochastic decision draws from a generator seeded from the world seed, the branch and the sequence, so a rumour roll on turn forty is the same roll on every replay.
  4. The tick is pure. Planning a step reads a world and returns the events that would happen, writing nothing. Committing is a separate step.

Weather, drives, level of detail and belief decay are all functions of the graph and the clock, so they never need to be written down to be stable.

Branches and snapshots

Storage is SQLite, four tables: branches, events, snapshots and session metadata. A branch is a line of events. Forking writes one row and shares everything before the fork with the parent, so a swipe costs nothing. Branch names are derived from where they forked, which keeps snapshots and tests stable across replays.

Folding from zero every time would be slow, so the store snapshots the world every two hundred events and folds forward from the newest snapshot valid for the branch. A snapshot holds the graph, the declared resources and their ledgers, and the declared situation kinds.

A session is one SQLite file. On restart the service reopens every file it finds, and a test asserts that a world comes back with its clock, its people, what happened, and which reply a swipe would take back.

The invariants

Because the simulation is pure and seeded, it can be run for ten thousand ticks in a test and checked against a list of properties that must never break. There are seventeen:

no-dangling-edges        every link points at nodes that exist
edge-time-order          nothing closes before it opened
single-heading           nobody is walking to two places
single-location          nobody is in two places at once
no-future-knowledge      nobody believes a fact before it happened
belief-bounds            confidence and distortion stay in 0..1
non-negative-debt        a debt is positive or closed
debt-conserved           settling a debt neither invents nor duplicates value
schedules-satisfiable    nobody's routine sends them somewhere unreachable or shut
plan-is-coherent         no plan without parties; none both one-off and standing
alias-is-coherent        no handle without a person, no two people on one handle
task-is-coherent         no task nobody set or nobody can do
offer-is-coherent        no offer nobody asked
thread-has-participants  no open situation with nobody in it
thread-stakes-bounds     stakes stay in 0..1
resources-conserved      the books balance for every declared quantity
resource-bounds          nobody holds more than the ceiling or less than the floor

Each rule's comment says what it does not catch. The debt rule, for instance, reads the graph and cannot see the coins that moved, so it checks that nothing was invented but not that the right amount was paid. Writing the gap down matters, because a rule read as stronger than it is would hide exactly the bug it appears to catch.

The model boundary

Only five files know a language model exists. The model interface is deliberately tiny, so the engine never depends on one provider's shape. There are exactly three system prompts in the codebase: the narrator, the narrator's structured-output variant, and the offline world generator. The world appears in the narrator's prompt only inside the brief, and a test asserts that.

Output comes back as prose plus tags. Tags are parsed by a small, strict parser: forgiving about quoting and whitespace, strict about shape, and a malformed tag is reported rather than guessed at. The adjudicator then resolves names, checks preconditions on a scratch world, and returns four lists: accepted, rejected, failures, events. Only the events are written.

Running it

bun install
bun test           # 794 tests
bun run day        # watch a day in the Docks
bun run brief      # the brief a narrator would get
bun run rumour     # watch one story travel the district and mutate
bun run play       # the whole loop; offline scripted narrator unless OPENROUTER_API_KEY is set
bun run serve      # the simulation as a service, for Marinara

Runs on Bun 1.4 or later, using its built-in SQLite, test runner and hashing. No runtime dependencies.
